## M0：基线与参数（当前阶段）

### M0.1 目录与文档

- `analysis/`：独立 uv 项目，入口与输出契约写入 README。
- `agents/`：预测接口与边界说明。
- `dashboard/`：明确为可砍的读模型。
- `chainlink/`：明确 CRE CLI simulation 的 bounty 文件位置。
- 根 `README.md`、`docs/ARCHITECTURE.md`、本路线图。

验收：这些文件存在；README 能让新机器从 `make check && make test` 开始；架构图标出单向依赖和 Chainlink 边界。

### M0.2 历史数据与定参

- 用 public JSON-RPC 拉 2–4 周 EIP-1559 `baseFeePerGas`。
- 对 `K ∈ {10, 25, 50, 100, 200}` 计算 K 块均值分布。
- 以 p10/p25/p50/p75/p90 生成候选桶，选 p90–p10 相对宽度最小的 K。
- 输出 `data/params.json`，不提交完整数据；提交最小 fixture 与测试。

验收：离线 pytest 通过；生成 JSON 的 `window_k` 与 `bounds_wei` 为正整数且严格递增；边界分桶与 Solidity 半开区间语义一致。

## M1：预测机器人与回测

- 统一接口：`forecast(history, horizon, bounds) -> probs[0..n]`，概率为 `1e18` 缩放并严格和为 `1e18`。
- naive：上一窗口均值；EWMA：固定衰减；TimesFM：独立推理进程，读取同一历史。
- 回测使用时间顺序切分，禁止未来信息泄露；输出 log score、Brier score、命中率与累计收益。

验收：三种 bot 对同一 fixture 产出合法概率向量；TSFM 失败时，演示仍能用 EWMA/naive 完成。

## M2：Anvil 竖切

- 部署合约与测试 token。
- 让三个 bot 事前记录预测；按预设 fee path 逐块设置 `anvil_setNextBlockBaseFeePerGas`。
- 任意账户提交 `sample()`；结算后展示 `PredictionScored` 和彩池 payout。

验收：演示命令在干净环境下跑完且无需外部 RPC；日志能解释「BASEFEE 是链上读取，不是 Chainlink 喂价」。

## M3：Chainlink CRE

- `chainlink/workflow.ts`：读取参数和预测 artifact，调用/编排本地模拟的 forecast step。
- `chainlink/simulate.sh`：不需要凭据、不部署、不改变合约结算权威。
- README 明确这是 sponsor track integration / orchestration，而非 oracle settlement。

验收：CRE CLI simulation exit 0；README 能从仓库根定位并运行它。

## M4：提交包

- 英文 README：问题、创新点、架构、运行命令、局限、CRE 文件位置。
- 录屏顺序：预测 → 下注 → 原生 base fee 采样 → settle → payout → AI log-score leaderboard。
- 附上定向测试与最终 Full Verify 结果。

验收：评审不看聊天记录，只看仓库和录屏，也能复现完整主线。
