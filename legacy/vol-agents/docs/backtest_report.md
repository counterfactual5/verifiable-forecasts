## Method

- Chronological walk-forward split: step `t` (for `t` in `[window, len(history))`) trains on the strict prefix `history[:t]` and is scored against `history[t]`, the block immediately after that prefix. Prefixes grow one block per step and never contain the scored value — no step sees future information.
- Probability vectors are integers on the e18 probability scale over `len(bounds) + 1` half-open buckets (bucket `i` = `[bounds[i-1], bounds[i])`), each vector summing to exactly 1e18 — the same shape and validation the onchain `recordPrediction` applies.
- Log score: integer-only `ln(p_win) * 1e18` with the same algorithm as the onchain scorer; `p_win = 0` is floored at `-18e18`. Offline and onchain settlement scores therefore agree within the documented error bound (< 1e9 absolute on the 1e18-scaled result).
- Brier: mean of `(p_win / 1e18 - 1)^2` on the realized bucket. Hit rate: fraction of steps where `argmax(probs)` equals the realized bucket (argmax ties broken toward the lowest bucket index).
- PnL model (as implemented in `agents_bots.backtest`): parimutuel pool — each step bets stake 1 on the argmax bucket against one equal-stake silent bot per bucket, so the pool holds `stake * (n_buckets + 1)`; a hit pays `stake * (n_buckets + 1) / 2`, a miss pays 0, and `cumulative_pnl = payouts - steps * stake` (with 5 buckets: +2 per hit, -1 per miss).
- The default bot list is `naive,ewma`: every forecast step spawns a fresh runner process, and each process cold-loads the TimesFM model, so a tsfm backtest costs one model load per step. Pass `--bots naive,ewma,tsfm` to include it.
